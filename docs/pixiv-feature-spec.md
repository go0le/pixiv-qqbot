# Pixiv 插画检索（当前行为）

这是维护者该看的行为说明，不是审核报告。早期 v1 规格只定义了「一个关键词 + 默认全年龄」。下面三条以代码注释和回归测试为准，并已经接到网络结果上。

## 检索规则

1. **普通多标签是 AND。** `/pixiv 信浓 泳装` 里「信浓」和「泳装」都要在作品标签或标题上命中。本地缓存和网络候选用同一套判断。作品上多出来的普通标签（微笑、背景）不算错。
2. **无关图只按 v3 的负向规则丢。** 同一互斥组里叠了两个及以上角色、且不是合集/多人物，丢掉。黑名单（猎奇、抽象整活、福瑞、BL 等）和 `aiType === 2` 丢掉。不是「标签集合必须等于用户输入」。
3. **灰名单默认避开。** 用户在明文里点名某一类（`r18`、`口交` / `フェラ` 等）时，只放行这一类，而且作品必须真有这一类；其它灰名单仍然禁止。R-18 认官方 `xRestrict > 0`，不认画师自己打的 `R-18` 标签。其余灰名单认标签或标题里的关键词。

黑名单词出现在用户输入里时，整次拒绝，不扣冷却。

数量默认 1 张，上限 3 张。最后一个纯数字是张数。会话冷却 15 秒。发出去的图下面附一行 `🎨 画师：{artist}`。

## 搜索与登录

- 没配 refresh token 时，请求 `www.pixiv.net` 的插画 AJAX。默认 `mode=safe`；明文要了 R-18 时用 `mode=r18`。
- 配了 `PIXIV_REFRESH_TOKEN` 且没设网页反代时，改走 `app-api.pixiv.net`。非 R-18 带 `filter=for_ios`；明文 R-18 去掉这个滤镜。
- `PIXIV_PHPSESSID` 或 `PIXIV_COOKIE` 会加到网页请求的 Cookie 上。
- `PIXIV_PROXY_BASE_URL` 当作 `www.pixiv.net` 的反代源站（路径与网页 AJAX 相同）。设了它就不再改打 app-api。
- 网页 `mode=r18` 的条目如果根本没有 `xRestrict` 字段，按官方 R-18 处理。字段在且为 0 时仍然拒绝。app-api 缺字段时不猜。
- 搜索先走 `10000users入り` → `5000` → `1000` → `500`，最后才是纯标签。每一档都再过 AND / 灰名单 / 互斥组 / 黑名单。
- HTTP 429 和 502/503/504 最多重试 3 次，间隔 1s、2s、4s（上限 8s）。401/403 不重试。

下载 `i.pximg.net` 时带 `Referer: https://www.pixiv.net/`。文件先写临时文件，核对 JPEG/PNG/GIF/WebP 魔数后再改名。

未映射的中文词默认原样当标签，不会去拉起本机 `agy`。只有 `PIXIV_LLM_TAGS=1` 时才调用外部模型补标签。

## 不在本说明里的旧草稿

`/pixiv purge`、`/pixiv ... --ai`、全局每分钟请求上限、按「会话 + 标签」分开记已发 PID，都没有实现。出图上限是 3，不是早期规格里的 5。
